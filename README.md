# 朝練シュートカウンター

バスケットボールのシュート練習を **声だけで記録する** スマホ向けアプリ（PWA）。
ボールを持ったまま「イン」「アウト」と言うだけで種目ごとの成功数・試投数が記録される。
床にスマホを置いて立ったまま読める大きな文字表示と、オフライン動作に対応する。

ビルド工程・パッケージマネージャ・外部サービスを一切使わない **静的ファイル 7 個だけ** で動く。

## 👉 スマホで開く

**<https://kyo-tsun.github.io/basketball-counter/>**

Android の Chrome でこの URL を開き、**⋮ → アプリをインストール**（または「ホーム画面に追加」）を選ぶと、
アドレスバーのない全画面アプリとして起動できる。一度開けば以降はオフラインでも使える。

---

## 主な機能

| 機能 | 内容 |
|---|---|
| 音声で記録 | 「イン」で成功 +1、「アウト」で失敗 +1、「次」で次の種目へ |
| 手動タッチ操作 | 騒がしい体育館や音声非対応端末でも 5 個のボタンで同じ操作ができる |
| 遠距離視認表示 | 成功数を画面短辺の 20〜30% の文字高で表示。床置きでも立った位置から読める |
| 練習メニューの編集 | 種目の追加・削除・並べ替え、目標本数の変更。メニューを最大 20 個まで保存して切り替え |
| 練習時間の計測 | 開始・一時停止・終了。目標合計に達した時点で達成時間を確定 |
| 練習履歴 | 最大 100 件。終了日時・達成時間・種目別の成功率を後から見返せる |
| 省電力ダークモード | 背景を真っ黒にし、再描画を毎秒 5 回以下に抑えてバッテリー消費を減らす |
| 画面スリープ防止 | 練習中に画面が消灯しない（Screen Wake Lock API 対応端末） |
| オフライン動作 | 一度開けば以降は通信なしで起動する。記録は端末内だけに保存され、外部へ送信しない |

## Android スマホで開く方法

Service Worker（オフライン動作）とホーム画面への追加を使うには **HTTPS または localhost** で配信する必要がある。
用途に応じて次のいずれかを選ぶ。

### 方法 A: 公開済みの URL を開く（おすすめ）

GitHub Pages で HTTPS 配信済みなので、Android の Chrome でそのまま開ける。

```
https://kyo-tsun.github.io/basketball-counter/
```

HTTPS で配信されるため、オフライン動作（Service Worker）とホーム画面への追加がどちらも使える。

`main` ブランチのルートを配信する設定になっているので、**`main` に push するとそのまま反映される**
（反映には数十秒〜数分かかる）。設定は GitHub のリポジトリページ → **Settings** → **Pages** で確認できる。

### 方法 B: PC から同じ Wi-Fi 経由で開く（公開したくない場合）

PC 側でこのリポジトリのディレクトリを配信し、スマホから PC の IP アドレスにアクセスする。

```bash
# リポジトリのルートで実行（どちらでもよい）
python3 -m http.server 8000
# または
node test/serve.js 8000
```

PC の IP アドレスを調べる（`192.168.x.x` のような値）。

```bash
hostname -I        # Linux
ipconfig getifaddr en0   # macOS
```

Android の Chrome で `http://192.168.x.x:8000/` を開く。

> `http://` の LAN アクセスでは Service Worker が登録されないため、オフライン動作とホーム画面追加は使えない。
> その場合はアプリが「オフライン利用の準備ができなかった。計測機能はそのまま使える。」と表示し、**記録機能はそのまま動く**。

### 方法 C: ファイルをスマホにコピーして開く

7 個のファイル（`index.html` / `app.js` / `manifest.json` / `sw.js` / `icon-192.png` / `icon-512.png` / `apple-touch-icon-180.png`）を
同じフォルダに入れてスマホへ転送し、ファイルマネージャから `index.html` を Chrome で開く。

`file://` でも記録・保存・履歴はすべて動作する（Service Worker のみ無効）。

### ホーム画面に追加する（方法 A のみ）

HTTPS 配信が必要なため、方法 B（`http://` の LAN アクセス）と方法 C（`file://`）では利用できない。

1. Chrome で開いた状態で右上の **⋮** をタップ
2. **アプリをインストール** または **ホーム画面に追加** を選ぶ
3. ホーム画面のアイコンから起動すると、アドレスバーのない全画面（standalone）で開く

## 使い方

### 1. 練習を始める

画面上部の **開始** をタップすると経過時間の計測が始まる。
開始を押し忘れても、最初に成功／失敗を記録した時点で自動的に計測が始まる。

### 2. 音声で記録する

1. ヘッダーの **音声** トグルをタップして ON にする
2. 初回はマイクの使用許可を求められるので **許可** する
3. シュートのたびに声に出す

| 言葉 | 動作 |
|---|---|
| 「イン」「入った」「マル」「まる」「○」 | 成功 +1（成功数と試投数の両方が増える） |
| 「アウト」「外れた」「はずれた」「バツ」「ばつ」「×」 | 失敗 +1（試投数だけ増える） |
| 「次」「つぎ」 | 次の種目へ |
| 「戻る」「もどる」「前」 | 前の種目へ |
| 「リセット」「やり直し」「やりなおし」 | 直前の 1 件を取り消す |

認識したテキストは画面下部のフィードバック領域に表示される（確定は太字、認識途中は斜体）。

**誤認識しにくくする工夫**

- 「アウトサイド」「インサイド」「ライン」「前半」「手前」などコマンド語を含む言葉は、除外語として登録済みなので反応しない
- 同じ種類のコマンドは 800ms 以内に連続して発行されない（「イン、イン」と早口で言うと 1 回だけ数える）
- 認識が途切れても自動で再開する（300ms → 600ms → … と待機時間を伸ばし、5 回続けて何も拾えなければ停止して手動操作を促す）

> 音声認識はブラウザの機能（Web Speech API）を使うため、**Android Chrome では通信が必要** になる場合がある。
> オフライン時や通信エラー時はメッセージを表示してトグルを OFF に戻すので、手動ボタンで記録を続けられる。

### 3. 手動ボタンで記録する

音声が使えない場面では 5 個のボタンで同じ操作ができる。音声認識を ON にしたままでも使える。

| ボタン | 動作 |
|---|---|
| 成功 | 成功 +1 |
| 失敗 | 失敗 +1 |
| 取り消し | 直前の 1 件を取り消す（最大 20 件までさかのぼれる） |
| 戻る / 次へ | 種目を 1 つ移動する（先頭・末尾では循環しない） |

種目一覧の行をタップすると、その種目をアクティブにできる（カウントは変わらない）。
**全カウント初期化** は確認ダイアログを経てから、全種目の成功数・試投数と操作履歴を 0 に戻す。

### 4. 練習を終える

**終了** をタップすると計測が止まり、履歴に 1 件保存される。
全体成功数が目標合計（既定は 125 本）に達した時点でも達成時間が自動で確定する。

試投が 1 回もない場合は履歴に保存されない。

### 5. メニューを編集する

**メニュー** をタップするとメニュー編集画面が開く。

- **メニュー一覧**: 各行にメニュー名・種目数・目標合計を表示。行をタップして選択し、**新規作成 / 複製 / 名称変更 / 削除 / 切り替え** を実行する
- **種目の編集**: 各行の **編集** で種目名・セクション名・目標成功数（1〜99）を変更、**↑ ↓** で並べ替え、**削除** で種目を消す（確認あり）
- **種目を追加**: 末尾に新しい種目を追加する
- **既定メニューに戻す**: 種目配列を初期状態（13 種目 / 125 本）に戻す（確認あり）

練習中に種目名・セクション名・目標本数を変更しても、記録済みの成功数・試投数はそのまま維持される。
種目を削除した場合はその種目の記録と操作履歴だけが破棄される。

メニューを切り替えると進行中の練習は終了し、記録があれば履歴に保存してから新しい練習が始まる（確認あり）。

### 6. 履歴を見る

**履歴** をタップすると、終了日時の新しい順に一覧が並ぶ。
各行に「終了日時・メニュー名・達成時間・成功数 / 目標合計・全体成功率・達成 / 未達」を表示する。
行をタップすると種目別の成功数・試投数・成功率が見られる。**削除** で 1 件だけ消せる（確認あり）。

### 7. 省電力ダークモード

ヘッダーの **省電力** トグルを ON にすると、背景が真っ黒・前景が無彩色になり、再描画が毎秒 5 回以下に制限される。
文字の大きさと画面の項目は通常モードと同じまま維持される。設定は次回起動時にも引き継がれる。

## データについて

- すべての記録は **端末のブラウザ内（localStorage）だけ** に保存され、外部へ送信されない
- 使用する鍵はすべて `vsc:` で始まる。それ以外の鍵は読み取らず、変更も削除もしない
- 保存されるもの: 進行中の練習、練習メニュー、選択中メニュー、設定（省電力）、練習履歴（最大 100 件）
- ブラウザの「サイトデータを削除」を実行すると記録は消える
- 同じ端末で 2 つのタブを同時に開くと、片方が「他のタブで練習が進行している」と表示して記録を停止する（データの取り違えを防ぐため）

## 対応環境

| 項目 | 条件 |
|---|---|
| ブラウザ | Android Chrome / iOS Safari（いずれも最新版） |
| 画面 | 短辺 320px 以上。長辺 568px 未満では種目一覧がセクション単位の集約表示に切り替わる。横向きにも対応 |
| 音声認識 | `SpeechRecognition` または `webkitSpeechRecognition` が必要。非対応端末ではトグルが無効になり手動操作を促す |
| スリープ防止 | Screen Wake Lock API。非対応端末ではメッセージを表示して記録機能のみ継続する |
| オフライン | Service Worker。`file://` や非 HTTPS では無効になるが記録機能はそのまま動く |

## ファイル構成

配布に必要なのは次の 7 個だけ。すべて同じフォルダに置き、相対パスのみで参照する。

```
index.html                 DOM + インライン CSS + PWA メタ情報
app.js                     全アプリケーションロジック（単一 IIFE）
manifest.json              PWA マニフェスト
sw.js                      Service Worker（precache + オフライン配信）
icon-192.png               マニフェスト用アイコン
icon-512.png               マニフェスト用アイコン
apple-touch-icon-180.png   iOS 用アイコン
```

`test/` と `.kiro/` は開発用であり、配布には不要（Service Worker のキャッシュ対象にも含まれない）。

```
test/                      テストハーネスと検証コード
.kiro/specs/               要件定義・設計・実装タスク・進捗
```

## 開発者向け

外部依存とビルド工程を持たないため、クローンしてブラウザで開くだけで動く。

### テストの実行

```bash
# Node で実行（DOM 検証以外の全件）
node test/run-node.js

# 個別の spec だけ実行
node test/run-node.js spec-serializer.js

# 乱数シードを固定して再現
VSC_SEED=12345 node test/run-node.js

# ブラウザで実行（DOM 検証を含む全件。静的サーバーが必要）
node test/serve.js
#   → http://127.0.0.1:8731/test/tests.html
```

- `test/tests.html` は `?seed=<整数>` でシードを固定できる
- DOM 層の検証（`test/spec-dom.js`）は `<iframe>` の同一オリジン制約があるため、`file://` では実行されない
- テストは 17 個の Correctness Property（プロパティベーステスト）と、例示・境界値・DOM 検証で構成される

### 設計方針

- **単一方向データフロー**: 入力（音声 / タッチ）→ コマンドディスパッチャ → 状態 → レンダラ → 永続化。音声由来とタッチ由来が同一経路を通る
- **純粋関数コアと副作用シェルの分離**: 正規化・コマンド判定・カウント遷移・直列化・表示算出は引数と戻り値だけで定義され、プロパティテストがブラウザ API のモックなしで成立する
- **永続化の隔離**: `localStorage` の呼び出しは Storage_Adapter の内部だけに存在し、公開関数はすべて Promise を返す
- **目標合計は派生値**: 125 本という数値はコードの計算経路に埋め込まず、常に選択中メニューの目標本数の合計として算出する

要件定義・設計・実装タスクは `.kiro/specs/voice-shot-counter-pwa/` にある。
